# 管理サイト

管理者ログインはユーザーの希望で保留中です。ローカルでは独立した管理サイトをサンプルデータで操作できます。本番ビルドでは未認証の管理画面をロックし、サンプル表示を有効にしません。

## ローカルで開く

既存の利用者サイトは5173 / API8787、管理サイトは5174 / API8788です。初回は `npm run db:local` で未適用のマイグレーションを反映します。

```sh
npm run admin:api
npm run admin:dev
```

[管理サイト](http://127.0.0.1:5174/) を開きます。サンプル操作は `machi-admin-preview-v1` に保存し、画面上のリセットで初期状態に戻せます。実データへの送信・課金・メール配信は発生しません。APIが停止した場合は接続エラーを表示し、通信失敗をサンプルで隠しません。

## 実装済みの管理機能

| 画面           | 操作                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------- |
| 概要           | 対応待ちの通報・返金・相談、開催予定、入金と原価、接続設定を確認                                   |
| 会員・招待     | 名前・メールで検索、国籍・街・興味・紹介を確認、理由を付けた利用停止と再開、30日間の招待登録と取消 |
| トーク・小部屋 | 募集の作成・編集・公開切替・中止、会議リンクの共有、同じトークの参加者4〜6人で小部屋を作成         |
| 予約・返金     | 状態による検索、参加の記録、返金待ちの決済をStripeで返金                                           |
| 通報           | 通報された投稿の確認、Workers AIによる分類の補助、対応済みの記録                                   |
| プロ相談       | 本人が同意した共有投稿、予算・希望日、受諾・有料成立・キャンセルの記録                             |
| 事業者         | 登録済み会員を事業者として登録、確認済みの記録・解除                                               |
| 現地メモ       | 情報確認日・事業との関係を含む投稿の作成・編集・公開切替                                           |
| メール配信     | 宛先・件名・試行回数の確認、未送信メールを再試行キューに戻す                                       |
| 採算           | 決済手数料・謝礼・人件費の累計を記録、入金と返金から差額を集計                                     |
| 操作履歴       | 管理者・操作・対象・実行日時を確認                                                                 |

トークを中止すると無料・未入金の予約をキャンセルし、決済済みの参加確定予約を返金待ちへ移します。通知は重複しないIDで配信キューへ追加し、返金はStripeの冪等キーを使う既存の処理で実行します。APIやメール配信の未接続を完了扱いにはしません。利用停止中の事業者を相談先から外し、新しい相談の送信もAPIで拒否します。小部屋や個人間の会話全文は管理画面から閲覧できません。通報された投稿と本人が相談のために共有した投稿だけを表示します。

一覧の検索は取得済みデータが対象です。会員500件、トーク・予約・メモ・配信・履歴・招待300件、通報・相談・小部屋100件が取得上限です。小規模運用の範囲を超える前に、サーバー側のページ分割・検索を追加してください。

## 技術の選定理由

- **独立したReact / TypeScript / Viteの入口**：利用者サイトとビルドを分け、利用者の画面に管理用UIを読み込ませず、既存の依存と開発手順を再利用します。出力先は `dist/community` と `dist/admin`。Viteの[ビルド構成](https://vite.dev/guide/build.html)に従い、それぞれのルートと設定を持たせています。
- **React Router**：各管理画面を固有のURLにし、再読込・戻る・画面への直接移動を可能にします。PCはサイドバー、スマホはメニューから2タップ以内で移動します。
- **CSS / Motion / Lucide**：既存依存で白いガラス調の画面、操作に伴う遷移、統一したアイコンを実装。新たなUIフレームワークは追加していません。動きを減らすOS設定に対応します。
- **Cloudflare Workerを別サービスとして配信**：利用者と管理のオリジン、静的資産、セッション、公開設定を分離します。Honoの共通処理を使い、管理用Workerは利用者APIを公開しません。利用者Workerの管理APIも404になります。
- **同じD1**：予約・会員・相談を複製せず同じデータを管理します。[D1のWorker API](https://developers.cloudflare.com/d1/worker-api/)でパラメーター化SQLとバッチを使用し、会員停止時のセッション失効などをまとめて実行します。
- **専用の管理セッションと許可メール**：将来のログイン用に `admin_sessions` を用意しました。管理セッション・`role=admin`・設定されたメールの一致をAPIごとに検証します。一般会員のCookieでは利用できません。管理者をこの画面から追加したり、権限を付与したりする機能は提供しません。
- **localStorageのサンプル環境**：ログイン実装を待たず、手元で画面と操作を確認するために使用。開発ビルドでのみ起動し、本番の認証判定を回避する仕組みには使用しません。

## 管理者ログインを再開するとき

初期指定は `danaoki30@gmail.com` です。`ADMIN_EMAILS` のカンマ区切り、または `ADMIN_EMAIL` で指定します。許可メールが空の場合は全員を拒否します。APIはアクセスのたびに許可メールと会員状態を確認します。

現在、管理用の `/api/auth/google` と `/api/auth/callback` は503で停止しており、管理セッションを発行する経路はありません。将来、Googleの検証済み本人情報・state・nonce・PKCEを検証した専用ログインからのみ発行してください。会員向けGoogleログインは管理セッションを発行しません。開発用の固定セッションはローカルの自動テスト専用で、マイグレーションや本番データには含めません。

Cookie名は開発用 `machi_admin_session`、本番用 `__Host-machi_admin_session` を使います。一般会員のセッションとは別テーブルです。利用者サイトと管理サイトは異なるホスト名で配信してください。

## 公開準備

`wrangler.admin.jsonc` は既存と同じCloudflareアカウント・D1を指定しています。配信先は `https://machi-admin.lildayne.workers.dev` です。管理者ログインは保留し、本番の未認証ロックを維持します。管理側にCronを設定せず、通知・返金の定期処理は利用者Workerだけが実行します。

```sh
npm run db:remote
npm run deploy
npm run deploy:admin
```

認証済みCLIと本番接続設定が必要です。未適用の0003〜0005を本番へ反映してから公開します。管理ログイン保留中の本番画面はロック表示です。管理用Workerが実際のメール・返金・AIを実行する際は、それぞれResend / Stripe / Workers AIの接続が必要です。

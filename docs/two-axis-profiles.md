# 留学相談と現地交流の2軸

2026年10月29日。今回のプロダクト変更の仕様。

## 目的と入口

Roamigoでは、留学を検討・準備する人が経験者に質問できることと、現地の学生・留学中の人・住民と知り合えることを両立する。ホームからそれぞれの検索へ1タップ、検索結果から1対1の会話へもう1タップで進める。既存の居住地検索、個人会話、受付停止、ブロック・通報は継続する。

会話をアプリ内で続けることだけを価値としない。将来の検証では、相談が解決したか、話したかった相手に会えたか、双方の希望で次の接点につながったかを軸ごとに確認する。外部SNSのアカウント情報を自動収集する機能は今回追加していない。

## プロフィール

立場は複数選択。たとえば、カナダ留学を経験し、現在は日本の学校に通い、次の留学も考えている人は3つとも選べる。立場はアプリ上の権限や本人確認の状態とは独立している。

| 対象                   | 入力欄                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------- |
| 共通                   | 表示名、国籍（必須）、写真、居住・滞在歴、興味、自己紹介、対応可能な時間、会話受付 |
| 留学を考える・準備する | 検討状況、知りたいこと、希望する国・地域（未定可、5件まで）                        |
| 留学経験を伝える       | 留学先、学校段階、留学形式、開始年・帰国年・期間、相談できるテーマ。経験は1〜5件   |
| 現地で交流する         | 現地の学生／現地に留学中／住民、交流できる地域、話せる言語、交流したいこと         |

留学経験者の国・地域は必須。年月・期間・相談テーマは任意。検討状況はボタン・セレクト・左右フリックで切り替えられる。

非選択の立場の欄は入力画面で閉じ、他の会員にはその立場の情報を返さない。本人の保存内容は保持し、再選択時に復元する。留学経験の入力途中の年・期間は非選択なら下書きとして保持し、経験者の立場で公開する際に再検証する。共通の自己紹介や居住歴は別の公開項目なので、立場を外してもそれらは消えない。会話受付を停止すると新規の検索結果から外れ、既存の会話は残る。

## 検索の意味

- **留学経験者に相談**：留学した国と相談テーマを組み合わせる。国が未定ならテーマだけでも探せる。複数の経験がある人は、同じ経験の中で国とテーマが一致する必要がある。
- **現地の人と交流**：交流先の国と、現地生・留学中・住民を選べる。交流地域が未登録なら現在の居住地を使い、過去の居住地や国籍から推定しない。
- 各軸の条件解除では軸を維持する。軸そのものを切り替えると前の検索条件を解除する。両軸のいずれも選ばない従来の検索も使える。

過去の留学先と現在の居住地は別の情報として保持する。たとえば「カナダ留学経験・現在東京の学生」の人は、カナダの留学相談と日本の現地生の交流に表示される。留学経験や現地生という立場は本人の申告であり、学校・エージェントによる確認済みとは表示しない。

## 実装と互換性

既存のReact・TypeScript、Cloudflare Worker・D1を継続。新しい立場の情報は `users.profile` 内の `participation` に保存する。既存の居住関係テーブルや会話の参加権限をそのまま使うため、新しいインフラやDBマイグレーションは不要。

検索条件と公開内容の判定を共通の純粋関数にし、WorkerのZodスキーマでも入力境界を検証する。Workerが公開用に非選択項目を取り除くので、画面で隠すだけにはしない。個人会話の相手情報にも同じ公開ルールを適用する。`verified` などの未定義属性は受け付けない。

旧クライアントが `participation` を送らずにプロフィールを更新した場合は、保存済みの値を引き継ぐ。既存の会員は、学生という立場を推測せず、従来の会話受付設定に基づく地域交流を継続できる。サンプルの留学経験はプレビュー専用。

留学相談への1,000円の買い切り課金は引き続き検証案。この変更では課金や利用権限を追加しない。高校生向けの本番募集に必要な年齢・所属確認や保護者対応の運用も、このプロフィールの自己申告とは分けて決める。

## 検証範囲

単体テストでは複数の立場、未定の希望先、国とテーマの組合せ、現在地との区別、非選択情報の公開制限、不正な属性を検証する。ブラウザテストではPCとモバイルで入力・検索・再読込・アクセシビリティを確認し、ローカルWorkerとD1に接続して保存・公開・1対1の会話まで確認する。

10月29日の検証結果：メイン・管理画面の本番ビルド成功、単体テスト61件合格。Playwrightは全121項目を実行し119項目が合格、PCの2項目は時間切れになったため、変更対象を含む11項目を個別に再実行して全件合格した。各項目の最新結果を合わせると121項目すべて合格。再実行では詳細トレースを無効にし、アニメーション・検証内容・タイムアウト値は維持した。別途、アプリ内ブラウザでも2軸の切替・現地生の絞込み・立場別フォームを操作し、幅320pxとPC幅で表示を確認した。

# イベントの雛形

2026年10月29日。「留学経験者への相談」「現地の人との交流」に合わせた一覧・詳細画面。今回は募集・決済の実運用を開始しない。

- 既存の `/talks` と `/talks/:id` を維持し、ナビ・ホーム・小部屋の表示名を「イベント」に揃える。
- 留学相談会、現地交流会、準備ワークショップ、街歩き交流の4つの企画サンプルを用意する。日時・料金・主催者など、未確定の項目は調整中・未定と表示する。
- 一覧では目的・開催形式・キーワード・保存済みで絞り込める。条件をURLに残し、再読込と組合せ検索に対応する。
- 詳細では対象者・テーマ・流れの案・開催形式・言語・主催情報を表示し、関連する会話相手と他のイベントへ進める。
- 保存は端末内の `roamigo-saved-events` のみ。通知登録やメール送信は行わない。申込ボタンは募集開始前として無効にする。
- 新画面から予約作成・キャンセル・CheckoutのAPIを呼び出さない。既存のバックエンド、会員情報、予約・会話の保存内容は変更しない。既存の募集URLも読み取り表示でき、予約記録は一覧に残す。

画面は既存のReact・TypeScript・Motionで構成し、白いガラスの素材・角丸・余白・色をプロフィール画面と統一する。留学相談を青、現地交流をセージ色で表す。新しい依存ライブラリや外部画像は追加しない。`src/lib/events.ts` の型と企画データ、`src/components/events.tsx` の画面、`src/events.css` の専用スタイルに分け、後から実際の開催データへ接続できるようにする。Cloudflareの構成・DBスキーマ・管理者認証は変更しない。

モバイルでは概要、受付状況、詳細の順に配置し、PCでは受付状況を右側に固定する。キーボードの移動順も表示順と一致させる。全画面のスケルトンと、動きを減らす設定は既存の仕組みを継続する。

イベントと会話相手の検索では、連続して条件を変えた際に直前の条件を失わないよう、最新のURLから検索条件を更新する。

検証：本番ビルドと単体テスト61件が成功。Playwrightは123項目を実行し122項目が合格、既存の地域検索で連続操作時の条件上書きを検出して修正後、関連9項目をPC・モバイル・実API接続で再実行し全件合格。各項目の最新結果で123項目すべて合格している。イベントの検索・保存・対面表示・320pxの表示幅・アクセシビリティ、既存予約と会員情報の保持、新画面からの更新API呼出しがないことを確認した。

最終のモバイル調整では検索条件をコンパクトにまとめ、企画を横長のカードにして、最初の企画名が初期表示の画面内に見えることも確認。関連12項目と、キーボードでカードを開く2項目を追加で再検証し、すべて合格した。

# 留学経験者の有料相談 仕様たたき台（MVP）

2026-11-11。前提：利用者が30分3,500円を払い、経験者に2,500円、Roamigoが1,000円（11/11にDanが60分3,000円から変更）。基本の検索と1対1の会話は無料のまま。エージェント課金はこの仕様に含めない（[agent-monetization-features.md](agent-monetization-features.md)）。

## 決めること（★は提案）
| 項目 | 選択肢 | ★提案 |
|---|---|---|
| 経験者への支払い | 月末に運営が手動で振込 ／ Stripe Connectで自動送金 | ★手動振込。月30件を超えたらConnect |
| 有料相談を受ける経験者の年齢 | 制限なし ／ 18歳以上 | ★18歳以上（送金・契約・税の扱いが単純。Stripe Connectも原則18歳以上） |
| 日程の決め方 | 既存の1対1チャットで調整 ／ 予約カレンダー | ★チャット＋候補日時3つ |
| 通話 | 経験者が Google Meet/Zoom のURLを入れる ／ アプリ内通話 | ★外部URL |
| 価格 | 固定30分3,500円 ／ 経験者が自由設定 | ★固定（検証のため） |

## 経験者の詳しいプロフィール（有料相談の前提）

有料で相談を受けるには、利用者が「この人に聞きたい」と判断できる情報が要る。今の「留学経験」欄（国・学校段階・形式・期間・相談テーマ、1〜5件）を広げる。

| 区分 | 項目 | 必須 | 公開 |
|---|---|---|---|
| 留学経験（1件ごと） | 国・都市 | 国は必須、都市は任意 | 公開 |
| | 学校名・プログラム名 | 任意 | 本人が公開／非公開を選ぶ |
| | 学校段階・形式・期間 | 既存のとおり | 公開 |
| | 滞在先（ホームステイ・寮・シェア等） | 任意 | 公開 |
| | エージェント利用の有無（使った・使わない） | 任意 | 公開。社名は書かせない（中立性のため） |
| | 費用の目安（帯で選ぶ） | 任意 | 公開 |
| | 出発前と帰国時の語学レベル（自己評価） | 任意 | 公開 |
| | 一番大変だったこと・よかったこと（短文） | 任意 | 公開 |
| 経歴 | 現在の所属（学生・社会人など）、学歴・職歴の要約 | 有料相談は必須（短文） | 公開 |
| | 相談できる言語 | 有料相談は必須 | 公開 |
| 関連記事 | アプリ内の体験記（既存の `notes` を経験者本人の投稿に広げる） | 任意 | 運営の確認後に公開 |
| | 外部リンク（ブログ・note・YouTube等、3件まで） | 任意 | 運営の確認後に公開。SNSの連絡先は不可 |
| 確認情報 | 年齢（18歳以上の確認）、在籍・修了がわかる書類 | 有料相談は必須 | **運営だけが見る**。公開側には「運営確認済み」の表示だけ |
| 相談の設定 | 受付ON/OFF、受けられる曜日・時間帯 | 有料相談は必須 | 公開 |

ルール
- 外部リンクと体験記は運営が確認してから表示する。連絡先の交換や外部決済への誘導になるものは載せない。
- 「運営確認済み」は書類を見たという意味だけで、経験の内容や相談の質を保証するものではないと明記する。
- 確認書類は確認後に削除し、確認日と確認者だけを残す。
- 無料の経験者（有料相談をしない人）は今までどおり任意項目だけでよい。

実装メモ：経験の追加項目は今の `users.profile.participation.experiences` に足せる。確認情報と承認は本人が書き換えられないよう別テーブルにする。体験記は既存の `notes` テーブル（`author_id`・`published`・`verified_at` あり）を流用できる。

## 流れ
1. **経験者が受付をONにする**：プロフィールの「留学経験を伝える」立場の中に「有料相談（30分 3,500円）を受け付ける」を追加。運営が承認した人だけ表示（18歳以上・本人確認）。検索結果とプロフィールに「有料相談可」バッジ。
2. **利用者が申し込む**：プロフィールまたは1対1会話から「有料相談を申し込む」。相談したいこと、希望日時の候補3つ。18歳未満は「保護者の同意を得た」チェック必須。この時点では支払いなし。
3. **経験者が承認する**：48時間以内に日時を1つ選び、通話URLを入れて承認（または辞退）。応答がなければ自動で失効。
4. **利用者が支払う**：承認後24時間以内に Stripe Checkout で3,500円。支払い完了で確定し、両者にメールと会話内のお知らせ。期限切れで自動キャンセル。
5. **実施**：開始時刻に会話画面から通話URLを開く。
6. **完了**：終了後、経験者が「実施した」を押す。利用者は72時間以内なら「問題を報告」できる。報告がなければ経験者への支払い対象になる。
7. **月末精算**：管理画面に経験者ごとの支払額一覧。運営が振込し「支払済み」にする。

## キャンセルと返金
| ケース | 扱い |
|---|---|
| 利用者が開始24時間前までにキャンセル | 全額返金 |
| 利用者が24時間を切ってキャンセル・無断欠席 | 返金なし。経験者に2,500円 |
| 経験者がキャンセル・無断欠席 | 全額返金。経験者に警告、2回で受付停止 |
| 利用者が問題を報告 | 運営が確認して返金を判断。それまで経験者への支払いを保留 |

## 禁止と安全
- アプリ外での直接決済、連絡先を交換して手数料を避けることを規約で禁止。
- 会話中の通報・ブロックは既存の仕組みを使う。有料相談中の通報は優先して対応。
- 経験者は「本人の申告による経験」であることを表示（学校やエージェントによる確認とは書かない）。
- 経験者がエージェント等から紹介料を受け取ることを禁止（中立性を守る）。

## 今のコードとの対応
| 必要なもの | 既存で使えるもの | 追加するもの |
|---|---|---|
| 決済 | 地域トークの Stripe Checkout・Webhook・返金処理（`bookings`、`stripe_events`） | 有料相談用のCheckout作成とWebhookの分岐 |
| 申込〜完了の記録 | — | テーブル `paid_sessions`（申込者、経験者、会話ルーム、状態、候補日時、確定日時、通話URL、金額3,500、経験者分2,500、手数料1,000、Stripe ID、期限、精算状態） |
| 受付設定・承認 | `users.profile.participation`、管理画面のユーザー操作、`audit_log` | 受付ON/OFFと運営承認のフラグ |
| 会話・通知 | 1対1会話（`direct_conversations`）、`email_outbox` | 会話内の申込カード、通知文面 |
| 精算 | 管理画面の売上集計 | 経験者ごとの支払一覧、支払済み記録。口座情報はアプリに保存せず、承認時にフォーム等で別管理 |

状態：`requested → accepted → paid → completed → settled`、分岐で `declined / expired / cancelled / refund_pending / refunded / disputed`。

## MVPに入れないもの
予約カレンダー、自動送金、レビュー、価格の自由設定、30分お試し、エージェント課金。

## 要確認（実装と並行で）
- 特商法の表記、利用規約・経験者向け規約。
- Roamigoが代金を受け取って経験者に払う形の法的整理（収納代行の扱い）と、経験者側の所得・確定申告の案内。Stripe Connectに移ると整理しやすい。

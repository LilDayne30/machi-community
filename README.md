# machi

京都の「喫茶店と街歩き」を最初の地域・テーマとする、旅行者、再訪者、住民向けの招待制Webアプリ。話したい相手を選び、1対1で旅の前後も会話を続けます。

スマホを優先した白いLiquid Glass UIです。下部ナビゲーションから主要画面へ1タップ、トーク詳細・会話へ2タップで移動できます。PCでは固定サイドバーになります。

## できること

- Google認証だけを使う招待制登録。関心・話せる時間・地域との関係・訪問予定の編集。
- プロフィールに国籍（必須）・街（任意）・興味のある国や地域（複数）・写真（任意）を登録。国籍未登録の会員は登録後にメッセージを送れる。
- 国籍・街の検索・興味のある地域で相手を絞り込み、地域タグや自分の興味から相手を探して1対1で会話を開始。
- 写真は選択時にプレビューし、プロフィール保存時に反映。削除・再登録と、相手一覧・会話アイコンへの表示に対応。
- 地域ホーム、テーマで絞れる現地メモ、情報確認日・投稿者の立場・利害関係の表示。
- 話せる人の一覧・テーマ検索・個人プロフィールから1対1の会話を開始。同じ相手なら同じ会話履歴に戻る。ホームの相手カードから1タップ、プロフィール確認を挟んでも2タップ。
- メッセージ一覧の初期表示は1対1。新しい会話の受付は本人が選択し、受付中の公開プロフィールだけが会員に表示される。ブロックは両者の送信を止める。
- 4〜6人・45分のオンライン地域トーク。初回無料、以降1回1,000円。残席・申込み・キャンセル・再決済。
- 参加者限定の小部屋、文章投稿、返信、未読、通報、投稿者の非表示。会話は12秒間隔で更新。
- 次の訪問ステータスを左右にフリックして変更。ボタンでも同じ操作が可能。
- 利用者が選んだ確認済み事業者への相談。予算・希望日・共有する自分の投稿を明示して同意。
- 運営管理：予約、参加記録、返金、通報、相談成立、部屋の組合せ、事業者確認、トーク募集、招待、現地メモ、原価記録、会議リンクのメール送信。
- 全画面スケルトン、画面遷移・モーダル・状態変更のアニメーション、動きを減らす設定への配慮、PWAマニフェスト。

地域トークの小部屋は、メッセージ画面の別タブで利用できます。自由な大規模グループ、GPS、自動送金、独自の通話は実装対象にしていません。

## 起動

Node.js 22.12以降、npmが必要です。

```sh
npm ci
cp .dev.vars.example .dev.vars
npm run build
npm run db:local
```

2つのターミナルで起動します。

```sh
npm run api:dev
npm run dev
```

<http://127.0.0.1:5173> を開きます。`.dev.vars` の `APP_ENV=development` と `DEMO_MODE=true` で、架空のデータを使う端末内プレビューが動きます。プレビューの予約は請求・実予約・外部送信を行いません。APIの会員権限はプレビューでも省略しません。

本番では `DEMO_MODE=false`、`APP_ENV=production` です。本番DBに架空の会員・店舗・トークは自動投入しません。

## 技術と選定理由

| 技術                               | 選んだ理由                                                                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| React 19                           | トーク、部屋、申込みなどの状態を共通化し、画面遷移を滑らかにするため。                                                                     |
| TypeScript                         | 予約状態・会話・同意内容の型を共有し、変更時の取り違えを検出するため。                                                                     |
| Vite                               | 小規模な会員向けアプリにSSRを必須とせず、軽い開発サーバーと静的ビルドを使うため。Next.js用の変換層を置かずWorkersへ配信できる。            |
| React Router                       | URLで画面を直接開けるようにし、ブラウザの戻る・進むにも対応するため。                                                                      |
| CSSのbackdrop-filter               | 白ベースのガラス表現をネイティブCSSで作るため。透過非対応でも白背景で読める。                                                              |
| Motion                             | 画面、確認ダイアログ、ステータスを同じ仕組みでアニメーションさせるため。                                                                   |
| Lucide                             | ナビゲーション・状態・操作のアイコンを統一し、SVGで鮮明に表示するため。                                                                    |
| Cloudflare Workers + Static Assets | フロントとAPIを同一オリジンで配信し、Cloudflareをバックエンドの中心にするため。                                                            |
| Hono                               | WorkersのRequest/Responseをそのまま扱い、認証・入力検証・権限確認をAPIにまとめるため。                                                     |
| Cloudflare D1 / SQLite             | 1地域・少人数での関係データをSQLで管理し、外部DBサービスを追加せずに運用するため。外部キー・一意制約・条件付きINSERTで整合性と残席を守る。 |
| Google OpenID Connect + jose       | Googleだけのログインを実装し、署名・発行者・対象・nonceを検証するため。認可コードフロー＋PKCEを使う。                                      |
| Zod                                | 型だけでは防げないAPIへの不正な入力や、AIの不正な出力を実行時にも検証するため。                                                            |
| Stripe Checkout / 公式SDK          | カード情報をアプリに保存せず地域トークの参加費を受け取るため。SDKで署名検証と冪等キーを扱う。                                              |
| Workers AI                         | 通報された投稿のテーマ分類・営業や勧誘の疑いを運営へ提示するため。人の確認を置き換えず、真偽や安全性を判定しない。                         |
| Resend HTTP API                    | 参加確定・返信・開催前・会議リンクのメールをWorkersから送るため。D1 outboxとCronで再試行する。                                             |
| Workers Cron Triggers              | 未入金予約の期限処理、開催前通知、メールと返金の再試行を15分間隔で行うため。                                                               |
| Web App Manifest + Service Worker  | ホーム画面追加と静的アセットの再利用に対応するため。会員APIや会話はキャッシュしない。                                                      |
| Playwright + axe-core              | デスクトップ・スマホ相当の実ブラウザで操作、画面幅、アクセシビリティを再現して検証するため。                                               |
| Vitest                             | 返金境界、送信元、トークン、Webhook署名などを高速に検証するため。                                                                          |
| GitHub Actions                     | リポジトリへの変更に対してビルドとテストを再実行し、レポートを残すため。                                                                   |
| Prettier                           | 1人開発でもAPI・画面・テストを読みやすい形式に統一するため。                                                                               |

この選定は、最初の案のSupabase / Vercel / Jevを、後から指定されたCloudflare中心の構成に置き換えています。D1はPostgreSQLのRLSを提供しないため、DBへの接続はWorkerのみに限定し、各APIで会員・部屋参加・相談宛先・管理者権限を確認します。SQLの外部キー・一意制約と、実際の権限テストも併用します。

1対1の会話は、既存の投稿・返信・未読・通知を使うため同じrooms/messagesモデルに載せ、固定の2人を `direct_conversations` で管理します。同じペアの一意制約と第三者の追加を拒否するSQLトリガーを併用し、APIでは本人同士の閲覧・送信とブロックを確認します。新しいバックエンドサービスは追加していません。運営者にも個人会話の一覧・全文は開示せず、本人が通報・相談共有した内容だけを対応画面へ渡します。

写真はブラウザのCanvas APIで最大512pxの正方形JPEGへ変換します。入力はJPEG・PNG・WebPの10MB以下、保存サイズは192KiB以下です。ブラウザで画像を描き直すことで元画像のEXIF等をコピーせず、サーバーでも形式・寸法・サイズを確認します。写真を小さく固定し、初期の少人数運用ではD1の `profile_photos` に会員ごと1枚を保存します。既存の会員権限と同じWorkerで保存・閲覧範囲を管理するための選定です。画像の枚数や容量を拡大する際は、バイナリをR2へ移す構成を想定しています。D1のバイナリ入出力は[公式の型変換仕様](https://developers.cloudflare.com/d1/worker-api/#type-conversion)に従います。

写真はログイン済みの閲覧対象者だけに返し、APIをキャッシュしません。写真用の外部URLはプロフィール更新APIから受け付けません。国籍や興味の地域は本人の入力で、検索は入力値に基づく絞り込みです。街からの国籍推定やAIによる相性判定は行いません。

## テスト

2026年10月22日のローカル検証は **98/98件合格**。詳細と未接続項目は [検証記録](docs/testing.md) に記載しています。

```sh
npx playwright install chromium
npm run test:all
npm audit
```

初回は `npm run db:local` を先に実行してください。テストはローカルDBのテスト用データを初期化します。開発中のローカルDBを保持したい場合はバックアップしてから実行してください。**テスト用会員・セッションを本番へ投入しないでください。**

- デスクトップとiPhone相当のChromiumで、申込み、キャンセル、保存、返信、通報、相談、フリック、管理、スケルトンを検証。
- 実際のローカルWorker / D1へアクセスし、部屋参加権限、相談の開示範囲、同意、CSRF、不正入力、同時定員管理を検証。
- Googleの実アカウントによるログイン、Stripeの実Checkout、実メール、リモートWorkers AIは、それぞれ接続設定後の追加検証が必要。
- レポートは `playwright-report/index.html`、JSONは `test-results/results.json`。スクリーンショットも `test-results/` に保存。

## 公開

詳しくは [公開手順](docs/deployment.md) を参照してください。

GitHub公開先は **LilDayne30/machi-community**、使用する確認済みメールは **danaoki30@gmail.com** に限定しています。

```sh
gh auth login --hostname github.com --git-protocol https --web --scopes user:email
npm run publish:github
```

公開スクリプトとpre-pushフックは、ログイン名・確認済みメール・送信先が一致しなければ停止します。既存の無関係なGitリポジトリのoriginは使いません。

## 構成

```text
src/                    画面、共通部品、型、端末内プレビュー
worker/                 認証、会員API、権限、決済、AI、Cron
migrations/             本番にも適用する空のDBスキーマ
public/                 アイコン、PWA、静的配信ヘッダー
tests/                  ブラウザ、API、セキュリティの検証
scripts/                アカウント確認と公開
.github/workflows/      CIとCloudflareへの手動デプロイ
```

画面の写真はUnsplashのリモート画像、フォントはGoogle FontsのDM Sans・Noto Sans JPです。本番では利用条件と、外部配信の可否を運営で確認してください。一般公開用の利用規約・プライバシーポリシーは運営内容に合わせて別途確定する必要があります。
